# ADR-0004: Egress enforcement — per-VM netns + transparent filter proxy

- **Status:** Accepted
- **Date:** 2026-09-02
- **Deciders:** Project team
- **Supersedes / Superseded by:** —

## Context

We must enforce a **deny-by-default egress allowlist** for each VM, from
**outside the guest** ([ADR-0001](0001-trust-and-threat-model.md)), while being
**rootless** and adding **no host firewall rules**. passt has no built-in
destination allowlist and always forwards outbound flows
([ADR-0003](0003-userspace-networking-passt.md)), but its outbound sockets live
in whatever network namespace the passt process runs in. That gives us a place
to intercept traffic that the guest cannot reach.

## Decision

Run passt inside a **per-VM private network namespace** (created via
**unprivileged user + network namespaces**). Inside that namespace, install
**transparent-redirect rules** that divert all of passt's outbound connections
to a host-side **Rust filter proxy**. The proxy recovers each connection's
**original destination**, checks it against the VM's **egress allowlist**
([ADR-0006](0006-allowlist-model.md)), and either **completes the connection
from the host namespace** or **drops it** and emits a `blocked` event. Because
the redirect rules live only in a namespace we own, the host's global firewall
tables are never modified.

## Details

```
VM (untrusted)
  │ vhost-user
  ▼
passt (stock) ─── runs in per-VM netns "sodabox-<id>" ────────────┐
  │ opens outbound sockets *inside* this netns                    │
  ▼                                                               │  rules scoped
nftables in the netns:  redirect all egress → filter proxy        │  to the netns,
  │  (original dst preserved via conntrack / SO_ORIGINAL_DST)      │  NOT host tables
  ▼                                                               │
Rust filter proxy  ── allowlist check on original dst ────────────┘
  │  allow → dial real dst in host netns and splice
  │  deny  → close + emit "blocked {ip,port,proto,ts}" event
  ▼
real host network
```

### Namespace & rootlessness

- The supervisor creates a user namespace (mapping the invoking user to
  "root-in-userns") and a network namespace it owns. `CAP_NET_ADMIN` /
  `CAP_NET_RAW` are held **only within that userns**, enabling `nftables` and
  transparent sockets there — never on the host. This mirrors how
  passt/pasta/rootless containers operate.
- One netns per VM → per-VM isolation and per-VM policy.

### Interception mechanism (locally-generated traffic)

passt's outbound flows are **locally generated by the passt process** inside the
netns. That matters for the nftables approach:

- **Primary: `nat`/`OUTPUT` REDIRECT (DNAT to the proxy).** Redirect TCP (and
  UDP, incl. DNS) egress to the proxy's local listener. The proxy recovers the
  intended destination with `SO_ORIGINAL_DST` (TCP) / `IP_RECVORIGDSTADDR`
  (UDP), preserved by conntrack. Well-trodden transparent-proxy pattern; works
  for locally-generated packets.
- **Alternative/if needed: `TPROXY`** in the `mangle` hook with `ip rule` +
  local routing. TPROXY is the more general transparent mechanism (keeps the
  original 4-tuple, better for non-TCP and full transparency) but is primarily
  aimed at *forwarded* traffic; using it for locally-generated sockets needs
  fwmark + policy routing. We start with REDIRECT + `SO_ORIGINAL_DST` for
  simplicity and move flows to TPROXY where transparency requires it.

> The choice is an internal detail behind a stable interface ("all VM egress
> reaches the proxy with its original destination recoverable"); it can change
> without affecting other ADRs. A spike will confirm which is needed per L4
> protocol.
>
> **Resolved by spike 0003** ([docs/spikes/0003-egress-interception.md](../spikes/0003-egress-interception.md)):
> use **TPROXY** as the primary mechanism — it uniformly handles TCP, UDP and
> QUIC and recovers the original destination directly (TCP `getsockname()`, UDP
> `IP_RECVORIGDSTADDR`) with no conntrack. Locally-generated traffic is brought
> into the PREROUTING TPROXY hook via a `mangle OUTPUT` mark + `ip rule fwmark`
> → `local default dev lo`. Plain `REDIRECT` + `SO_ORIGINAL_DST` works for TCP
> only (it cannot recover the UDP original destination) and remains a fallback.

### The filter proxy

- Rust (tokio). One proxy instance per VM, part of the supervisor
  ([ADR-0007](0007-control-plane.md)).
- Per-connection: read original dst → evaluate against the VM allowlist (static
  IP/CIDR entries **and** DNS-derived ephemeral entries, ADR-0005/0006) →
  allow+splice or deny+log.
- Allow path dials the real destination from the **host** namespace, so passt
  itself never needs host network reach.
- Emits structured events (`allowed`/`blocked`, with 5-tuple + matched rule +
  timestamp) on the VM's event stream for the TUI ([ADR-0009](0009-cli-and-tui.md)).
- **Fail-closed:** if the proxy is down or policy can't be evaluated, egress is
  denied.

## Consequences

- **Positive:** Enforcement is entirely outside the guest and unbypassable by a
  root app in the VM; no host firewall rules (scoped to a private netns);
  rootless; per-VM isolation; a natural, structured observability point for the
  TUI; passt stays stock.
- **Negative / costs:** Extra hop and a userspace splice per connection (some
  throughput/latency cost); the proxy must handle TCP and UDP (and connection
  tracking) correctly; more moving parts per VM.
- **Risks & open questions:**
  - Confirm REDIRECT vs TPROXY per protocol via a spike (esp. UDP/QUIC and
    ICMP handling — ICMP may be dropped or handled separately).
  - Verify `SO_ORIGINAL_DST`/`IP_RECVORIGDSTADDR` work as expected for
    locally-generated traffic inside the userns netns.
  - Non-TCP/UDP protocols (e.g. raw ICMP from guest) — decide allow/deny policy.
  - Performance of userspace splicing for high-throughput apps; consider
    `splice(2)`/`SO_SPLICE` optimizations later.

## Alternatives considered

- **Patch passt's `fwd_nat_from_tap()`** to consult an allowlist — single
  cleanest chokepoint, but a maintained fork with policy inside the
  packet-exposed process (ADR-0003). Deferred.
- **In-guest nftables/agent** — bypassable by root in the guest; excluded by
  ADR-0001.
- **Host firewall (nft/iptables) per VM** — needs root and modifies the host;
  violates core constraints.
